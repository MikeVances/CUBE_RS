# EDGE Test Registry

Короткий справочник по актуальным тестам и вспомогательным сценариям в `EDGE/tests`. Для запуска большинства интерактивных скриптов достаточно выполнить `PYTHONPATH=$PWD python EDGE/tests/<script>.py`. Pytest‑сценарии запускаются через `PYTHONPATH=$PWD pytest EDGE/tests/<file>::<case>`.

## Интеграционные и эмуляционные утилиты

| Файл | Назначение |
| --- | --- |
| `device_network_emulator.py` | Создаёт виртуальную Modbus‑шину с набором устройств (KUB/VFD/ESQ) для стендового тестирования. |
| `interactive_emulator.py` | CLI над эмулятором, позволяет вручную отправлять команды, поднимать виртуальные устройства и отслеживать ответы. |
| `load_test.py` | Полноценный нагрузочный тест: прогоняет опрос нескольких устройств через эмулятор, измеряет задержки и устойчивость. |
| `simple_load_test.py` | Упрощённая нагрузка для быстрых проверок (минимальная конфигурация устройств и короткий цикл). |
| `test_edge_with_emulator.py` | Pytest‑набор, который разворачивает DeviceNetworkEmulator и проверяет полный цикл сбора данных приложением EDGE. |

> ℹ️  Для низкоуровневой эмуляции Modbus RTU через PTY используйте сценарии из `EDGE/tools/simulators` (см. `EDGE/tools/simulators/README.md`). Они заменяют старые shell‑скрипты и позволяют быстро поднять виртуальную шину без запуска Python‑эмулятора из раздела `EDGE/tests`.
| `test_edge_health.py` | Интеграционные тесты Health API, валидация конечных точек и обработки ошибок. |
| `test_edge_offline.py` | Проверяет поведение системы в offline‑режиме (авторизация, кэш DeviceRegistry, HealthAPI). |

## Живые тесты устройств

| Файл | Назначение |
| --- | --- |
| `test_vfd.py` | Интерактивный Modbus‑тест для VFD. Может читать всю карту адаптера или отдельные регистры (`--regs`). |
| `test_esq230.py` | Живой тест ESQ‑230 c адаптером, поддерживает настройку размера пакета (`--batch`). |
| `test_kub1063.py` | Подробный опрос КУБ‑1063 через input‑регистры, соответствует документации по датчикам. |
| `test_kub1112.py` | Аналогичный живой тест для КУБ‑1112 (разделение holding/input, обработка спец значений). |
| `verify_kub1063_registers.py` | Сравнивает карту адаптера с официальной документацией: проверяет наличие адресов, типы регистров, масштабы. |

## Pytest‑наборы и вспомогательные проверки

| Файл | Назначение |
| --- | --- |
| `test_device_scheduler.py` | Большой pytest‑набор: проверяет планировщик устройств, yaml‑конфигурацию, приоритеты и реальные сценарии. |
| `test_modbus_protocol.py` | Юнит‑тесты парсинга/формирования Modbus‑кадров (crc, тайм‑ауты, ошибки). |
| `test_room_data_snapshot.py` | Проверяет механизм snapshot’ов комнатных данных и сериализацию в storage. |
| `test_telegram_offline.py` | Быстрый smoke‑тест Telegram бота в offline‑режиме (без реального API). |
| `test_edge_health.py` | Интеграционные проверки Health API (см. выше). |
| `conftest.py` + `fixtures/` | Общие фикстуры для pytest: фейковые устройства, настройки scheduler, мок‑storage. |

## Конфигурации и вспомогательные файлы

- `config/` – примерные секреты и журналы, используемые тестами (dev пароль, master.key, security.log).
- `__pycache__/` – артефакты Python; удаляются автоматически.
- `README.md` (этот файл) – актуальный реестр.
- `fixtures/` – набор тестовых данных и мок‑файлов (примерные snapshots, фейковые базы) для pytest‑кейсов.

Если появятся новые тесты, добавляйте строку в таблицу с кратким описанием и ссылкой на соответствующий документ.
