# 📋 ОПИСАНИЕ СТРУКТУРЫ ПРОЕКТА CUBE_RS

## 🏗️ Общая архитектура

CUBE_RS - распределенная система промышленного мониторинга КУБ устройств с поддержкой P2P туннелей, мобильных приложений и централизованного управления.

```
📱 Mobile/Web APP    ↔    🌐 SERVER    ↔    📡 EDGE Device
     │                        │                   │
 ┌───▼───┐              ┌───▼───┐           ┌───▼───┐
 │ User  │              │ Auth  │           │ Multi │
 │ Auth  │◀─────────────│ & Key │◀──────────│Device │
 │       │   JWT Auth   │ Mgmt  │  API Keys │ Mgmt  │
 └───┬───┘              └───┬───┘           └───┬───┘
     │                      │                   │
 ┌───▼───┐              ┌───▼───┐           ┌───▼───┐
 │ Farm  │              │Device │           │ KUB   │
 │ & API │◀─────────────│Registry│◀──────────│1063/12│
 │       │   REST API   │       │ Heartbeat │ Data  │
 └───┬───┘              └───┬───┘           └───┬───┘
     │                      │                   │
 ┌───▼───┐              ┌───▼───┐           ┌───▼───┐
 │ P2P   │              │Tunnel │           │Variable│
 │ UI    │◀─────────────│Broker │◀──────────│System │
 └───────┘   WebRTC     └───────┘   Data    └───────┘
```

## 📡 EDGE - Устройства мониторинга

**Назначение:** Локальные устройства для мониторинга промышленных контроллеров КУБ-1063, КУБ-1112 и других.

### Структура EDGE/
```
EDGE/
├── 🏗️ core/                    # Основные модули системы
│   ├── device_adapters/        # Адаптеры для разных типов КУБ
│   │   ├── base.py            # Базовый класс адаптера
│   │   ├── factory.py         # Фабрика адаптеров
│   │   ├── kub1063.py         # Адаптер КУБ-1063 (вентиляция)
│   │   ├── kub1112.py         # Адаптер КУБ-1112 (отопление)
│   │   └── variable_system.py # Гибкая система переменных
│   ├── device_registry.py      # Центральный реестр устройств
│   ├── edge_authentication.py # Аутентификация с SERVER
│   ├── tunnel_integration.py  # P2P туннели
│   └── [другие модули...]
├── 📁 config/                  # Конфигурационные файлы
│   ├── app_config.yaml        # Основная конфигурация
│   ├── devices.yaml           # Конфигурация устройств
│   └── secrets/               # Зашифрованные секреты
├── 📚 docs/                    # Документация EDGE
├── 🚀 start.py                 # Точка входа приложения
├── 📋 requirements.txt         # Python зависимости
└── 🔒 .gitignore              # Исключения Git
```

### Возможности EDGE:
- ✅ **Multi-device architecture** с Variable System
- ✅ **Modbus RTU/TCP** коммуникация с КУБ устройствами
- ✅ **Device Registry** для управления множеством устройств
- ✅ **Authentication Client** с API ключами от SERVER
- ✅ **P2P Tunnel Client** для прямого доступа
- ✅ **Heartbeat Service** для мониторинга состояния
- ✅ **Telegram Bot** для уведомлений и управления

### Поддерживаемые устройства:
- **КУБ-1063** - система вентиляции (температура, влажность, CO2)
- **КУБ-1112** - система отопления (пламя, температура, реле)
- **Расширяемость** через Variable System для новых устройств

## 🌐 SERVER - Центральный сервер

**Назначение:** Центральный сервер аутентификации, управления устройствами и координации P2P туннелей.

### Структура SERVER/
```
SERVER/
├── 🔐 auth_system.py          # Система аутентификации и ролей
├── 🚀 tunnel_broker.py        # P2P туннель брокер  
├── 🛠️ admin_cli.py            # CLI для администрирования
├── 📱 mobile_app.py           # Поддержка мобильных приложений
├── ⚡ resilient_tunnel_broker.py # Отказоустойчивый брокер
├── 🐳 docker-compose.yml      # Docker развертывание
├── 🌐 nginx/                  # Веб-сервер конфигурация
├── 🔧 systemd/                # Linux службы
├── 📋 requirements.txt        # Python зависимости
└── 🔒 .gitignore             # Исключения Git
```

### Возможности SERVER:
- ✅ **JWT & API Key аутентификация** для пользователей и устройств
- ✅ **Role-based Access Control** (ADMIN, FARM_OWNER, VIEWER, EDGE_DEVICE)
- ✅ **Device Registry & Management** централизованного
- ✅ **P2P Tunnel Broker** IXON-style с WebRTC координацией
- ✅ **Admin CLI** для управления пользователями и устройствами
- ✅ **Docker deployment** с Nginx и SSL
- ✅ **Health Monitoring** системы и устройств

### Роли пользователей:
- **ADMIN** - полные права управления системой
- **FARM_OWNER** - управление своими фермами и устройствами
- **VIEWER** - только просмотр данных  
- **EDGE_DEVICE** - права устройств для отправки данных

## 🔐 Безопасность

### Базовая безопасность
- **JWT токены** для APP пользователей (короткий срок жизни)
- **API ключи** для EDGE устройств (долгоживущие)
- **Role-based permissions** для всех операций
- **Encrypted secrets** в конфигурационных файлах
- **SSL/TLS** для всех сетевых соединений

### 🛡️ Защита от MITM атак
Система включает продвинутые модули защиты от атак "человек посередине":

#### Certificate Pinning
- **SHA256 pinning** серверных сертификатов
- **Public Key pinning** (более устойчив к обновлению сертификатов)
- **Автоматическое извлечение** и сохранение отпечатков сертификатов
- **Проверка срока действия** pins с автоматическим обновлением

#### Mutual TLS (mTLS)
- **Certificate Authority** для создания клиентских сертификатов
- **Взаимная аутентификация** клиент-сервер
- **Автоматическая генерация** сертификатов для EDGE устройств
- **Валидация цепочки** сертификатов

#### Детекторы атак
- **Certificate change detection** - обнаружение смены сертификатов
- **DNS spoofing protection** - проверка резолвинга в приватные IP
- **Suspicious content analysis** - анализ ответов на XSS/injection
- **Security headers validation** - проверка заголовков безопасности

#### Расположение модулей
Готовые к использованию модули находятся в `_archive/security/`:
- `mitm_protection.py` - основная защита от MITM 
- `mutual_tls.py` - взаимная TLS аутентификация
