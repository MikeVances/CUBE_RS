# 🚀 Руководство пользователя EDGE системы

*Процесс настройки от получения устройства до мониторинга КУБ устройств в Telegram*

## 📋 Исходные данные пользователя:
- ✅ Устройство с установленной EDGE системой
- ✅ Telegram Bot API ключ 
- ✅ Сеть из 10 устройств:
  - 8x КУБ-1063 (вентиляция/климат)
  - 2x КУБ-1112 (горелки/обогрев)

---

## 🔧 ШАГ 1: ФИЗИЧЕСКОЕ ПОДКЛЮЧЕНИЕ

### 1.1 Подключение к КУБ устройствам
```
EDGE устройство → RS485 → Сеть КУБ устройств
```

**Настройка сети:**
- Каждое КУБ устройство должно иметь **уникальный Slave ID** (1-10)
- RS485 подключение: `A+`, `B-`, общий `GND`
- Скорость: 9600 бод (стандарт для КУБ)
- Последнее устройство в цепи - терминальный резистор 120 Ом

### 1.2 Подключение к интернету
- Ethernet кабель или WiFi настройка
- EDGE система должна иметь доступ к Telegram API

## 🔐 ШАГ 2: НАСТРОЙКА TELEGRAM БОТА

### 2.1 Настройка API ключа
```bash
# Подключиться к EDGE устройству (SSH/консоль)
cd /path/to/EDGE

# Настроить Telegram бот
python tools/telegram_secrets_cli.py set-token YOUR_BOT_TOKEN_HERE
```

### 2.2 Добавление администраторов
```bash
# Добавить себя как администратора (нужен Telegram ID)
python tools/telegram_secrets_cli.py set-admins YOUR_TELEGRAM_ID

# Или добавить несколько администраторов
python tools/telegram_secrets_cli.py set-admins 111111111,222222222,333333333
```

### 2.3 Проверка настройки
```bash
python tools/telegram_secrets_cli.py show
```

## 🏭 ШАГ 3: КОНФИГУРАЦИЯ УСТРОЙСТВ

### 3.1 Редактирование конфигурации устройств
```bash
nano config/devices.yaml
```

### 3.2 Пример конфигурации для 10 устройств:
```yaml
devices:
  # Корпус 1 - Вентиляция
  - device_id: 1
    device_type: "KUB-1063"
    slave_id: 1
    name: "Корпус 1 - Климат"
    description: "Основная система вентиляции"
    enabled: true
    location: "Корпус №1"
    
  - device_id: 2
    device_type: "KUB-1063" 
    slave_id: 2
    name: "Корпус 2 - Климат"
    description: "Вторая система вентиляции"
    enabled: true
    location: "Корпус №2"
    
  # ... еще 6 КУБ-1063 (slave_id: 3-8)
  
  # Горелки
  - device_id: 9
    device_type: "KUB-1112"
    slave_id: 9  
    name: "Горелка основная"
    description: "Основная система обогрева"
    enabled: true
    location: "Котельная"
    
  - device_id: 10
    device_type: "KUB-1112"
    slave_id: 10
    name: "Горелка резервная" 
    description: "Резервная система обогрева"
    enabled: true
    location: "Котельная"
```

### 3.3 Настройка RS485 порта
```bash
nano config/app_config.yaml
```

Найти секцию `modbus` и указать правильный порт:
```yaml
modbus:
  port: "/dev/ttyUSB0"  # или /dev/ttyS0, COM1 в Windows
  baudrate: 9600
  timeout: 3
```

Система автоматически отправит уведомления при:
- 🚨 **Критичные аварии:** Обрыв датчиков, превышение лимитов
- ⚠️ **Предупреждения:** Отключенные датчики, незначительные отклонения

## 🔧 РАСШИРЕННАЯ НАСТРОЙКА

### 8.1 Добавление нового устройства
1. Физически подключить к RS485 сети
2. Настроить уникальный Slave ID на устройстве  
3. Добавить в `config/devices.yaml`:
```yaml
- device_id: 11
  device_type: "KUB-1063"
  slave_id: 11
  name: "Новое устройство"
  description: "Описание"
  enabled: true
  location: "Место установки"
```
4. Перезапустить систему: `python start.py --reload`

### 8.2 Отключение проблемного устройства
Если устройство создает помехи, временно отключите его:
```yaml
- device_id: 5
  device_type: "KUB-1063"
  slave_id: 5
  name: "Проблемное устройство"
  enabled: false  # ← Отключить
```

### 8.3 Изменение интервалов опроса
В `config/app_config.yaml`:
```yaml
modbus:
  polling_interval: 30  # секунд между опросами
  timeout: 5           # таймаут ответа устройства
  retries: 3           # количество повторных попыток
```

## ❓ РЕШЕНИЕ ПРОБЛЕМ

### Устройство не отвечает
1. Проверить физическое подключение RS485
2. Проверить Slave ID устройства
3. Проверить скорость (9600 бод)
4. Посмотреть логи: `tail -f logs/reader.log`

### Telegram бот не работает  
1. Проверить API токен: `python tools/telegram_secrets_cli.py show`
2. Проверить интернет соединение
3. Проверить права администратора
4. Посмотреть логи: `tail -f logs/telegram_bot.log`

### Высокая нагрузка на RS485
1. Увеличить интервал опроса в конфигурации
2. Отключить неиспользуемые устройства
3. Проверить качество кабелей RS485
