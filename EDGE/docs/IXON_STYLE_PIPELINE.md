# 🌐 IXON-Style P2P Pipeline для EDGE

Реализация pipeline аналогичного IXON системе: EDGE устройство с серым IP регистрируется на брокере с белым IP, пользователи подключаются через прямые P2P туннели.

## 🏗️ Архитектура Pipeline

```
📱 Пользователь (любой IP)          🌐 Брокер (белый IP)          🏭 EDGE (серый IP)
        │                                    │                           │
        │                                    │                           │
     ┌──▼──┐                            ┌────▼────┐                 ┌────▼─────┐
     │Web  │◄──1. Авторизация──────────►│ Tunnel  │◄─2. Регистрация─┤   EDGE   │
     │App  │                            │ Broker  │                 │ Tunnel   │
     │     │◄──3. Запрос адреса────────►│         │                 │ Client   │
     │     │                            │         │                 │          │
     └──┬──┘                            └─────────┘                 └────▲─────┘
        │                                                                │
        └──────────────4. Прямой P2P туннель──────────────────────────────┘
                              (трафик минует брокер)
```

## 🔄 Этапы Pipeline

### 1. Регистрация EDGE устройства
```bash
# EDGE устройство запускается и регистрируется на брокере
python start_tunnel_client.py
```

**Что происходит:**
- EDGE запускает локальный API сервер (порт 8080)
- Регистрируется в Tunnel Broker с метаданными:
  - Farm ID, Owner ID, возможности устройства
  - Локальный IP, порт API
  - Список КУБ устройств и их статус
- Начинает отправлять heartbeat каждые 5 минут

### 2. Авторизация пользователя
```bash
# На брокере запущено веб-приложение
python tunnel_system/mobile_app.py --broker http://broker-domain.com:8080
```

**Что происходит:**
- Пользователь заходит на веб-приложение
- Вводит логин/пароль
- Получает список доступных ферм (только своих)

### 3. Инициализация P2P соединения
**Веб-приложение:**
- Выбирает ферму из списка
- Создает WebRTC offer
- Отправляет запрос на соединение через брокер

**Tunnel Broker:**
- Получает запрос от пользователя
- Уведомляет EDGE устройство через WebSocket
- Координирует обмен WebRTC offer/answer

**EDGE устройство:**
- Получает уведомление о запросе соединения
- Создает WebRTC answer
- Отправляет answer через брокер

### 4. Прямой P2P туннель
**Результат:**
- Устанавливается прямое WebRTC соединение пользователь ↔ EDGE
- Весь трафик идет напрямую, минуя брокер
- Пользователь получает полный доступ к EDGE Remote Dashboard API

## 🚀 Быстрый запуск всего pipeline

### На сервере с белым IP (брокер):

```bash
# 1. Запуск Tunnel Broker
cd tunnel_system
python tunnel_broker.py --host 0.0.0.0 --port 8080

# 2. Запуск веб-приложения для пользователей
python mobile_app.py --broker http://localhost:8080 --host 0.0.0.0 --port 5000
```

### На EDGE устройстве (серый IP):

```bash
# Настройка окружения
export TUNNEL_BROKER_URL="http://your-domain.com:8080"
export OWNER_ID="user_unique_id"
export FARM_NAME="Моя EDGE ферма"

# Запуск EDGE Tunnel Client
python start_tunnel_client.py
```

### Для пользователя:

1. Открыть `http://your-domain.com:5000`
2. Зарегистрироваться/войти
3. Выбрать свою ферму из списка
4. Нажать "Connect" → установится P2P туннель
5. Получить полный доступ к данным КУБ устройств

## 📊 API Endpoints через P2P туннель

После установки P2P соединения доступны:

```javascript
// Tunnel System совместимые
GET /api/data/current        // Текущие данные всех устройств
GET /api/data/statistics     // Статистика фермы
GET /api/device/{id}         // Данные конкретного устройства
GET /health                  // Проверка состояния

// Прокси к оригинальным EDGE API
GET /api/edge/devices        // Список устройств
GET /api/edge/devices/status // Статус всех устройств  
GET /api/edge/alarms         // Активные аварии
GET /api/edge/types          // Типы устройств
```

## 🔐 Безопасность Pipeline

### Уровень аутентификации
- SHA256 хеширование паролей
- Сессионная авторизация
- Доступ только к своим фермам

### Уровень сети  
- WebRTC end-to-end шифрование
- Прямые P2P соединения (трафик не проходит через брокер)
- Временные ограничения на запросы соединения

### Уровень API
- API прокси с контролем доступа
- Изоляция локальных ресурсов EDGE
- Логирование всех обращений

## 🎯 Преимущества IXON-style подхода

### ✅ Преимущества:
- **Минимальная задержка** - прямые P2P соединения
- **Масштабируемость** - брокер не передает трафик данных
- **Безопасность** - WebRTC шифрование + аутентификация
- **Доступность** - работает через NAT и Firewall
- **Экономия трафика** - брокер используется только для координации

### ⚠️ Особенности:
- Требует WebRTC поддержку в браузере (есть везде)
- Первичная регистрация через брокер
- Heartbeat для поддержания регистрации

## 🔧 Переменные окружения

### Для EDGE Tunnel Client:
```bash
TUNNEL_BROKER_URL="http://broker-domain.com:8080"  # Обязательно
FARM_ID="edge-unique-farm-id"                      # По умолчанию: edge-hostname  
OWNER_ID="user_unique_identifier"                  # Обязательно для авторизации
FARM_NAME="Название фермы"                         # Отображаемое имя
EDGE_API_PORT="8080"                              # Порт локального API
```

### Для Tunnel Broker:
```bash
BROKER_HOST="0.0.0.0"
BROKER_PORT="8080" 
DATABASE_PATH="tunnel_broker.db"
```
