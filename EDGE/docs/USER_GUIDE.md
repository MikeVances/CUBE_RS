# Руководство пользователя EDGE

Документ описывает, как работать с системой мониторинга EDGE: что показывают панели веб‑дашборда и какие команды доступны в Telegram‑боте. Материал рассчитан на операторов и техников, которые ежедневно следят за состоянием вентиляции, нагрева и приводов ESQ/VFD.

## 1. Веб‑дашборд

### 1.1 Авторизация и запуск
1. Откройте адрес, выданный при установке системы (пример: `http://edge.local:8501`).
2. Введите логин/пароль, если включена авторизация.
3. Дождитесь загрузки главной страницы – она автоматически подтянет последние данные с устройств.

> СКРИН – главный экран после входа

### 1.2 Структура главной страницы
- **Шапка**: текущий объект, время последнего обновления и индикатор связи с RS‑485.
- **Карточки устройств**: каждая плитка отражает отдельный контроллер или привод. Цвет рамки показывает статус: зелёный – норма, жёлтый – предупреждение, красный – авария, серый – устройство недоступно.
- **Панель уведомлений**: список последних аварий/предупреждений с возможностью квитирования.

### 1.3 Карточка устройства
> СКРИН – карточка ESQ-230

Каждая карточка содержит:
- Название и идентификатор (например, `ESQ-230 #4`).
- Краткие показатели: выходной ток, мощность, заданная/фактическая частота, напряжение DC шины, температурные датчики и т. д.
- Строка «Аварии»: показывает `Норма` либо текст последней активной ошибки (коверкается адаптером).
- Время последнего успешного опроса.

#### Подсказки по показателям
| Показатель | Что значит | Единицы |
|-----------|------------|---------|
| Выходной ток | Текущий ток на выходе инвертора | А
| Выходная мощность | Реальная мощность привода | кВт
| Заданная частота | Уставка привода (часто ≤ 50 Hz) | Hz
| Напряжение звена DC | Напряжение на конденсаторах DC-шины | V
| Температура IGBT/мотора | Нагрев силовых ключей/мотора | °C

Если значение выделено синим, оно интерактивное – клик отобразит расшифровку и историю.

### 1.4 Фильтрация и поиск
- Поле «Поиск устройства» фильтрует карточки по имени, типу или ID.
- Выпадающий список «Показать только…» позволяет оставить на экране устройства с авариями, предупреждениями или отключённые.
- Кнопка «Обновить» вручную запрашивает свежие данные (при активном автообновлении это не требуется).

### 1.5 Просмотр подробностей
1. Нажмите на карточку устройства.
2. Откроется модальное окно со вкладками:
   - **Параметры** – полный список регистров с описанием и статусом (ок/ошибка/спецзначение).
   - **Журнал** – история последних аварий/предупреждений по устройству.
   - **Графики** – тренды выбранных параметров (частота, температура, нагрузка).

> СКРИН – модальное окно с вкладками

### 1.6 Работа с уведомлениями
- Панель уведомлений отображает «живые» события из DeviceScheduler.
- Для каждого события указано устройство, тип (авария/предупреждение), описание, время появления.
- Экран «Аварии» позволяет просмотреть список всех активных событий (см. скрин ниже). Сейчас квитирование реализовано только в Telegram‑боте; в веб‑интерфейсе события исчезают автоматически после того, как устройство вернётся в норму.

> СКРИН – таблица «Аварии и предупреждения»

### 1.7 Типовые действия
| Ситуация | Что делать |
|----------|------------|
| Карточка серого цвета | Проверить физическое подключение/RS‑485. После восстановления связи карточка обновится автоматически. |
| Красная рамка | Перейти в подробности, посмотреть код ошибки, прочитать подсказку. При необходимости – связаться с техподдержкой или сбросить аварию на устройстве. |
| Зависшие данные | Нажать «Обновить». Если не помогает – проверить лог `logs/edge.log` или перезапустить `start_edge.py`. |

## 2. Telegram‑бот

EDGE включает Telegram‑бота для оперативного мониторинга. Он отправляет оповещения и позволяет получить статус устройств прямо в мессенджере.

### 2.1 Подключение
1. Найдите бота по имени, указанному при установке (пример: `@edge_monitor_bot`).
2. Нажмите «Start».
3. Введите команду `/auth <код>` – код выдаётся администратором (содержится в `config/bot_secrets.json`). После авторизации бот запомнит вас.

> СКРИН – диалог с ботом после авторизации

### 2.2 Основные команды
| Команда | Назначение |
|---------|------------|
| `/help` | Список доступных команд и краткая справка. |
| `/status` | Общий статус системы: активные устройства, количество аварий, время последнего цикла. |
| `/devices` | Список устройств с кратким статусом (норма/авария/нет связи). |
| `/device <id>` | Детальная информация по конкретному устройству (ключевые показатели, последние события). |
| `/alerts` | Текущие активные аварии/предупреждения, если есть. |
| `/subscribe` / `/unsubscribe` | Включает или выключает push‑уведомления об авариях. |
| `/ack <alert_id>` | Квитирование конкретного предупреждения прямо из чата (единственный способ квитировать событие в текущей версии). |

### 2.3 Оповещения
- Бот автоматически рассылает сообщения, когда устройство переходит в состояние аварии/предупреждения, а также когда оно восстанавливается.
- В сообщении указывается: устройство, тип события, текст и ссылка на дашборд.
- Если включено квитирование, бот предложит кнопки «Подтвердить»/«Отложить».

> СКРИН – пример уведомления об аварии

### 2.4 Лучшие практики
- Оставляйте включённой команду `/subscribe` для дежурных – так любые аварии приходят мгновенно.
- Используйте `/device <id>` после оповещения, чтобы свериться с показаниями датчиков.
- Для периодических отчётов можно настроить cron, который вызывает `/status` через Bot API и логирует результат.

## 3. Советы по эксплуатации

1. **Проверяйте время опроса.** Если устройства отвечают слишком долго, увеличьте `poll_interval` в `config/devices.yaml`.
2. **Следите за обновлениями адаптеров.** Новые регистры/масштабы попадают в `EDGE/core/device_adapters`. После обновления – запустите `verify_kub1063_registers.py` или аналогичный скрипт, чтобы убедиться, что UI показывает корректные значения.
3. **Архивируйте логи.** Файлы в `logs/` быстро растут. Настройте ротацию либо периодически копируйте их на отдельный сервер.
4. **Используйте эмулятор для тестов.** Для проверки без реального железа запустите `PYTHONPATH=$PWD python EDGE/tests/device_network_emulator.py` и затем откройте дашборд – вы получите полностью симулированную сеть.

## 4. FAQ

- **Данные не обновляются, хотя связь есть.** Проверьте `DeviceScheduler` в логах (`start_edge.py`). Возможно, очередь опроса блокируется медленным устройством.
- **Бот не пишет ничего в чате.** Убедитесь, что токен и `admin_users` настроены в `config/bot_secrets.json`, а пользователь прошёл `/auth`.
- **Почему значения отличаются от реального прибора?** Убедитесь, что используются правильные масштабы (см. README адаптера). Если устройство обновлено, проверьте новые адреса регистров.
